# ALDAR Boxing — UI/UX судалгаа ба дизайны төлөвлөгөө

Огноо: 2026-11-12. Зорилго: одоо mobile-first дизайн бэлтгэх, дараа нь Android APK хөгжүүлэх.

## 1. Арга ба хязгаар

README, package.json, үндсэн хуудас, layout, CSS, бүртгэл/ирц/таймер/санхүүгийн компонентууд, өгөгдлийн загвар болон API хэрэгжилтийг уншив. Өмнөх README нь create-next-app-ийн ерөнхий загвар байсан.

Энэ нь кодод тулгуурласан UX аудит. Браузерт ажиллуулж хараагүй, хэрэглэгчтэй ярилцаагүй, contrast эсвэл гүйцэтгэлийг хэмжээгүй. Хэрэглэгчийн хэрэгцээ, хугацаа, зорилтот үзүүлэлтүүд нь баталгаажуулах санал. node_modules байхгүй тул локал Next.js гарын авлагыг унших боломжгүй байсан; аппын код өөрчлөөгүй.

## 5. Гол урсгалын дүрэм

1. Ирц: өдөр → анги → сурагч → ирсэн тэмдэглэх → амжилт. Буцаах боломжтой байна. Бөөн бүртгэлд анги/огноо/хүний тоог харуулж баталгаажуулна. Хэсэгчилсэн алдаа, давхар даралтыг тусад нь шийднэ.
2. Шинэ сурагч: зайлшгүй мэдээлэл → анги → хяналт → хадгалалт → дэлгэрэнгүй. Алдаанд оруулсан утга алдагдахгүй. Регистр, цусны бүлэг, хаягийг зайлшгүй талбар болгох хэрэгцээг судална. Төлбөр аваагүй хүнийг автоматаар төлсөн болгохгүй.
3. Төлбөр: сурагч → дүн/хугацаа/эхлэх өдөр/арга → дуусах өдөр ба нийлбэр → баталгаажуулах → түүх, орлого шинэчлэгдэх. Сунгалт өнөөдрөөс үү, одоогийн эрх дууссанаас уу гэдгийг тодорхой болгоно. Тарифыг тохиргооноос авна; MemberDetailModal дахь 150000 гэсэн тогтмолыг арилгах ажил төлөвлөнө.
4. Устгах: дэлгэрэнгүйн нэмэлт үйлдэлд байрлуулж, нэр ба нөлөөлөх бүртгэлийг харуулна. Архивлах/бүрэн устгах дүрмийг өгөгдлийн бодлоготой хамт шийднэ.
5. QR: одоогийн үнэмлэх үүсгэх боломжийг хадгална. Ирээдүйн scanner-д permission, татгалзсан, буруу QR, давхар ирц, сүлжээгүй төлөвийг загварчилна. QR-ийн хуучирсан төлөвийг эрхийн үнэн зөв эх сурвалж болгохгүй.

## 6. Дизайн системийн эхний санал

Чиглэл: спортын дүр төрх, бараан суурь, улаан үндсэн үйлдэл. Нэр, цаг, төлөв хамгийн тод байна.

| Token | Санал |
| --- | --- |
| Background / Surface / Raised | #09090B / #18181B / #27272A |
| Primary / Secondary text | #FAFAFA / #A1A1AA |
| Primary action | #DC2626; pressed/disabled/focus хувилбартай |
| Success / Warning / Error | #34D399 / #FBBF24 / #F87171; текст/icon дагалдана |
| Typography | Гарчиг 24/32, хэсэг 20/28, үндсэн 16/24, туслах 14/20 |
| Spacing | 4, 8, 12, 16, 24, 32; утасны зах 16 |
| Radius | Товч/талбар 12, карт 16, sheet 24 |
| Controls | Веб гол товч/талбар 48 CSS px өндөр; Android native 48dp хүрэх талбай |
| Navigation | Системийн safe area, keyboard нээгдэх төлөвийг тооцох |

Өнгө бүрийн хослолыг хэмжиж батална. WCAG 2.2 AA: энгийн текст 4.5:1, том текст 3:1 contrast. Minimum target 24 CSS px нь үл хамаарах нөхцөлтэй; төслийн утасны дизайн илүү том талбай зорьж байна. [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [Android accessibility](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views).

Компонентын багц: Button, IconButton, TextField, Select, SearchField, StatusBadge, MemberCard, SessionCard, StatCard, EmptyState, ErrorState, Skeleton, Toast, ConfirmDialog, BottomSheet, BottomNav. Фонтын Монгол кирилл дүрс ба fallback-ийг бодит төхөөрөмжөөр шалгана.

## 7. Төлөв болон responsive шалгалт

- Жагсаалт: loading, өгөгдөлгүй, хайлт олдоогүй, алдаа/retry, амжилт, хуучирсан өгөгдөл.
- Маягт: талбарын алдаа, хадгалж буй, амжилттай/амжилтгүй, хадгалаагүй өөрчлөлттэй буцах.
- Таймер: бэлэн, раунд, амралт, түр зогссон, дууссан, дуугүй, background-оос буцсан.
- 360/390/412 CSS px утас, 768 tablet, 1280 desktop; урт нэр, том дүн, 200% текст/zoom, keyboard, landscape.
- Desktop-д хуваарь/ирц хоёр багана байж болно; утсанд нэг багана. Сүүлийн мөр, үндсэн үйлдэл доод навигацад дарагдахгүй.
- Dialog/sheet: нэр, анхны focus, focus буцаалт, keyboard, Android Back-ийн тодорхой зан төлөв.

## 8. Хэрэглэгчийн судалгаа

Дасгалжуулагч, бүртгэл/удирдлагаас нийт 3–5 хүнтэй 20–30 минутын ярилцлага, ажиглалт хийнэ. Ирц, төлбөр сунгах, шинэ сурагч нэмэх ажлыг үзүүлүүлж дараалал, давтамж, алдаа, төхөөрөмж, сүлжээний нөхцөлийг тэмдэглэнэ.

Шийдэх асуултууд: хамгийн их ашигладаг дэлгэц; QR-ийн бодит хэрэгцээ; сарын эрхийн сунгалтын дүрэм; төлбөргүй хүний ирц; сүлжээгүй үед зайлшгүй хийх ажил; дэлгэц унтарсан үед таймерын шаардлага.

Prototype даалгавар: өнөөдрийн ангид ирц бүртгэх, сурагч хайж төлбөр сунгах, шинэ сурагч ангид оруулах, 3 минутын раунд эхлүүлэх. Эхний зорилт: тусламжгүй гүйцэтгэл ≥90%, энгийн ирц ≤3 үндсэн даралт, төлбөрийн дүн/хугацааг зөв ойлгох. Baseline хэмжсэний дараа тохируулна. Жижиг сорьцыг нийт хэрэглэгчийн статистик гэж үзэхгүй.

Хугацаа нь нэг дизайнер/хөгжүүлэгчийн анхны төсөөлөл; саналын давталт, хэрэглэгчийн оролцооноос хамаарна.

| Үе | Ажил | Үр дүн | Дуусах шалгуур |

| 0 · 1–2 өдөр | Ярилцлага, одоогийн baseline | Хэрэгцээ, бизнесийн дүрэм, эрэмбэлсэн асуудал | Гол урсгал тодорхой |
| 1 · 1–2 өдөр | Navigation, flow, wireframe | 6 үндсэн дэлгэцийн бүдүүвч | Ирц/бүртгэл/төлбөрийн урсгал бүтэн |

Одоогийн дараагийн ажил: үе 0–3. Энэ баримт батлагдсан макет эсвэл ажиллагаатай prototype-ийг орлохгүй.

Веб хэрэгжилтийн дараалал: P0 төлбөр/огноо/хадгалалтын дүрэм → token/компонент → хуваарь/ирц → сурагч/бүртгэл → төлбөр/санхүү → таймер. Код бичихийн өмнө dependency суулгаж AGENTS.md-ийн локал Next.js гарын авлагыг уншина.

## 10. APK-д бэлтгэх чиглэл

Одоо mobile-first UI, дахин ашиглах дизайн token, бизнесийн дүрэм ба платформын боломжуудыг салгах чиглэл баримтална. Эцсийн stack-ийг төхөөрөмжийн туршилтаар шийднэ.

| Хувилбар | Боломж | Баталгаажуулах зүйл |
| --- | --- | --- |
| Веб UI + Capacitor | React/CSS ажлыг дахин ашиглах | WebView, camera, файл хуваалцах, safe area, Back, background timer |
| React Native/Expo | Native mobile интерфэйс тусад нь хөгжүүлэх | UI дахин хэрэгжүүлэх зардал, API/type дахин ашиглалт, lifecycle |

Сонголтоос өмнө жижиг техникийн prototype хийнэ. Одоогийн Next.js сервер/API болон fs хадгалалтыг APK дотор шууд ажиллана гэж үзэхгүй.

Зайлшгүй бэлтгэл:

- Backend ажиллуулах орчин, тогтвортой database, backup/restore, authentication, үүргийн эрх.
- API base URL, session/token, input validation, давхар төлбөр/ирцээс хамгаалалт, аудитын бүртгэл.
- Offline хэрэгцээний шийдвэр. Эхний хувилбарт сүлжээгүй үед хадгалсан мэт харуулахгүй; queue/conflict/retry бодлогыг тусад нь төлөвлөх.
- QR payload дахь утас зэрэг хувийн мэдээллийг багасгах; scanner-д серверээр эрх/ирц баталгаажуулах.
- Camera permission ба татгалзсан төлөв, keyboard resize, Back, export/share, timer lifecycle-ийг бодит төхөөрөмжөөр шалгах.
- Signing, application ID, version, тест түгээлт, APK/AAB хүргэлтийн checklist.
